01 / ERROR HANDLING

Break it.
Handle it.

Try the validator below. It uses a custom error class, throw, try/catch and finally to turn bad input into a user-friendly message.

Build Validator

Enter a project name. An empty or very short name intentionally triggers a custom validation error. 

class ProjectError extends Error {
  constructor(message) {
    super(message);
    this.name = "ProjectError";
  }
}

try {
  validateProject(name);
} catch (error) {
  showFriendlyMessage(error);
} finally {
  resetForm();
}

The project workflow demonstrates repository creation, branching, pushing a feature, opening a pull request and merging back into main.

Command sequence

$ git clone repository-url
$ git checkout -b feature/error-handling
$ git add .
$ git commit -m "Add custom error handling"
$ git push origin feature/error-handling

$ git checkout main
$ git pull origin main
$ git merge feature/error-handling

In the real submission, these commands are executed against the student's GitHub repository.

Workflow goal:

Keep the stable main branch protected while development happens on a feature branch. A pull request gives the change a review point before it becomes part of the main project.

03 / NPM BASICS

Package the
project.

NPM provides the project manifest, dependency management and repeatable scripts for running development tasks.

Essential commands

npm init -y — create package.json
npm install — install dependencies
npm install <package> — add a package
npm uninstall <package> — remove a package
npm run dev — run development script
npm list — inspect installed packages
